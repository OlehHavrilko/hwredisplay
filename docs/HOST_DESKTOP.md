# Windows-хост: датчики, трей и оптимизация

Документ описывает второй этап хоста: расширенный каталог датчиков, работу в трее, системную интеграцию и измерения нагрузки. Контракт для телефона не изменился, см. [PROTOCOL.md](PROTOCOL.md).

## Каталог датчиков второго этапа

| Группа | Источник | Что публикуется | Проверено на этой машине |
| --- | --- | --- | --- |
| CPU | Win32 `GetSystemTimes` | загрузка по времени | было на первом этапе |
| RAM | Win32 `GlobalMemoryStatusEx` | занято, всего, процент | было на первом этапе |
| GPU: загрузка | PDH `\GPU Engine(*)\Utilization Percentage` | `gpu.utilization.percent` по адаптеру | 0,2 % в простое |
| GPU: видеопамять | PDH `\GPU Adapter Memory(*)\Dedicated Usage` + DXGI `IDXGIAdapter1::GetDesc1` | занято, всего, процент заполнения | 3,1 из 15,8 ГиБ, 19,6 % |
| Диски | PDH `\PhysicalDisk(*)\Disk Read Bytes/sec`, `Disk Write Bytes/sec`, `% Idle Time` | чтение, запись, активность (`100 − idle`) | два NVMe, 4 МиБ/с на C: |
| Температуры и вентиляторы | LibreHardwareMonitor 0.9.6 | `*.temperature.*`, `*.fan.*` | GPU 53 °C, память 52 °C, Hotspot 54 °C |

Правила, которые задают смысл значений:

- Инвентарь GPU берётся из DXGI, а не из WMI: WMI обрезает `AdapterRAM` до 4 ГиБ, DXGI отдаёт настоящий объём выделенной памяти. `deviceId` выводится из вендора, модели и порядкового номера среди одинаковых адаптеров, поэтому карточки переживают перезапуск. LUID используется только для сопоставления счётчиков PDH текущего сеанса.
- Загрузка чипа повторяет логику диспетчера задач: сумма вклада процессов внутри движка, затем максимум по движкам адаптера.
- Агрегат `_Total` в каталог дисков не попадает: сумма по дискам имеет другой смысл, чем отдельное устройство. Имя устройства берётся из имени экземпляра PDH (`Диск 0 (C:)`).
- Счётчики PDH всегда открываются английскими путями (`PdhAddEnglishCounterW`): на русской Windows локализованные имена не совпадают с документацией.
- Дифференциальные счётчики дают достоверное значение со второго сбора. До этого датчики остаются в состоянии `waiting`, а не показывают ноль.
- Ноль градусов у работающего ПК считается недоступным датчиком: LHM отдаёт `0`, когда чтение через драйвер не удалось. У вентилятора ноль допустим — он может стоять. Поэтому `Core (Tctl/Tdie)` на этом стенде честно помечен как «датчик не поддерживается», а не показывает `0 °C`.
- Если LHM не смог открыть оборудование, провайдер не публикует датчики и запоминает причину в `FailureReason`; остальные группы продолжают работать. Управление железом не используется: `IControl` не вызывается, режимы вентиляторов не меняются.

## Трей и системная интеграция

Хост запускается без окна: единственный постоянный интерфейс — значок в трее. Окно настроек и QR-кода создаётся по требованию и освобождается при закрытии; после закрытия WPF-поверхность и таймер интерфейса в простое не работают.

| Возможность | Поведение |
| --- | --- |
| Запуск | Без окна. Окно открывается само только при первом запуске (нет сопряжённых телефонов) или с ключом `--window`. |
| Меню трея (правая кнопка) | Настройки и QR-код, состояние сервера и число телефонов, копирование данных подключения, запуск и остановка сервера, отзыв конкретного телефона, автозапуск, правило брандмауэра, выход. |
| Окно настроек | QR-код, адрес, отпечаток, код приглашения, таблица датчиков, список телефонов. Создаётся по пункту меню, закрывается обычным крестиком. |
| Двойной щелчок | Открывает окно настроек. |
| Автозапуск | Ключ `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` со строкой `"<путь>" --tray`. Прав администратора не требует, службу не создаёт. |
| Запуск с автозагрузки | `--tray` — окно сразу остаётся в трее, сервер поднимается как обычно. |
| Правило брандмауэра | Отдельный повышенный запуск того же файла (`--firewall-add` / `--firewall-remove`) выполняет `netsh advfirewall`: только этот EXE, только TCP 18443-18445, профиль `private,domain`, `remoteip=localsubnet`. |
| Выход | Только из меню трея: останавливает сервер, закрывает драйверы датчиков и завершает процесс. |

Таймер оболочки раз в секунду обновляет только текст значка. QR-код, таблица датчиков и список телефонов существуют лишь пока открыто окно. Состояние правила брандмауэра и автозапуска читается при открытии меню и после изменения: проверка правила запускает `netsh`, поэтому в секундном таймере её быть не должно.

## Оптимизация

| Что сделано | Зачем |
| --- | --- |
| Снимок сериализуется при первой отправке и раздаётся всем сокетам | При отсутствии клиентов сборщик не кодирует JSON. |
| Окно переиспользует индексы каталога и пропускает уже показанный снимок | Индексы строятся при смене каталога, таблица обновляется по свежим данным. |
| Каталог сериализуется только при смене ревизии | Каталог меняется раз в 10 секунд, а не каждый тик. |
| Включено сжатие WebSocket (`permessage-deflate`) | JSON из повторяющихся имён датчиков сжимается в несколько раз, это трафик и батарея телефона. |
| Индекс «датчик → провайдер» строится при смене каталога | Опрос больше не перебирает провайдеров для каждого датчика на каждом тике. |
| В трее обновляется только значок | Скрытое окно не рендерит QR и таблицы. |
| Состояние брандмауэра кешируется | Проверка правила запускает процесс `netsh`; в секундном таймере это стоило больше, чем весь сбор датчиков. |

### Измерения на этой машине

AMD Ryzen 5 5600 (6 ядер, 12 потоков), Radeon RX 9060 XT, два NVMe, Windows 11, один подключённый телефон (эмулятор).

| Показатель | Как измерено | Результат |
| --- | --- | --- |
| CPU хоста, только трей | `TotalProcessorTime` за 60 с после прогрева | 0,53 с → 0,07 % мощности машины (0,9 % одного ядра) |
| CPU хоста, открыто окно | то же | 0,44 с → 0,06 % мощности машины |
| Память хоста, только трей | `WorkingSet64` / `PrivateMemorySize64` | 132 МиБ / 49 МиБ |
| Память хоста, после открытия и закрытия окна | `WorkingSet64` | 199 МиБ: WPF-сборки остаются загруженными до выхода |
| Трафик телефона | `wlan0` в `/proc/net/dev` эмулятора за 60 с | 15–17 КиБ/мин ≈ 250–290 Б/с при 20 датчиках |
| Размер APK | `assembleDebug` против `assembleRelease` | 41 МБ → 8,0 МБ (arm64), 6,4 МБ (armeabi-v7a), 9,0 МБ (x86_64) |

Стартовые цели из [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md): медиана CPU ≤1 % мощности машины, working set ≤250 МиБ. Обе выполняются с запасом по CPU и вплотную по памяти — память держат LHM и три запроса PDH.

## Лицензии

LibreHardwareMonitorLib 0.9.6 распространяется под MPL-2.0; в поставку попадают её сторонние компоненты с отдельными условиями. Перед публикацией сборки нужны SBOM и уведомления, как указано в [ARCHITECTURE.md](ARCHITECTURE.md). PDH, DXGI и Win32 — системные API Windows.

## Что не проверено

- Добавление правила брандмауэра требует подтверждения UAC: код и параметры `netsh` готовы, но интерактивное подтверждение в прогоне не нажималось. Состояние правила читается без прав администратора.
- Запуск при входе в Windows проверен на уровне ключа реестра (тест включает, проверяет и восстанавливает прежнее значение), но не полным перезаходом в систему.
- Пункты меню трея не проверялись автоматическим UI-тестом. Проверено другое: без аргументов процесс поднимается без окна (`MainWindowHandle = 0`) и телефон получает живые значения; с `--window` окно открывается, а после закрытия процесс остаётся жив и окна больше нет.
- Загрузка GPU под игровой нагрузкой не измерялась: в простое значение 0,2 %, что правдоподобно, но пик не подтверждён.
- Температуры CPU на этом стенде недоступны (LHM отдаёт 0, значение отброшено). Нужен прогон на машине, где датчик читается, или запуск с правами администратора.
