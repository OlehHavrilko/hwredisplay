# Технический проект HardwareDisplay

HardwareDisplay превращает Android-телефон в настраиваемый экран датчиков Windows-ПК. Начальная версия рассчитана на одну локальную сеть, один активный ПК на телефоне и работу панели на переднем плане. Подключение сохраняется по идентичности ПК, адрес можно обновить вручную. ## Состояние прототипа

Собран Windows-хост первого этапа: реальные CPU и RAM, сопряжение по приглашению, TLS с проверкой отпечатка и поток WSS. Android-клиент ещё не начат, поэтому сценарий «телефон показывает панель» на физическом устройстве не проверен.

| Часть | Состояние | Чем проверено |
| --- | --- | --- |
| `Core`: каталог, расписание опроса 1 с, статусы датчиков, ревизии | готово | тесты сборщика и формы сообщений |
| `Windows`: CPU через `GetSystemTimes`, RAM через `GlobalMemoryStatusEx` | готово | тест на реальных показаниях этой машины |
| Идентичность: ECDSA P-256, самоподписанный leaf, DPAPI `CurrentUser` | готово | тесты создания, перезагрузки и защиты файла |
| HTTPS: `/v1/session`, `/v1/pair`, фильтр `Host` и `Origin`, `no-store` | готово | тесты и живой запуск приложения |
| WSS `/v1/telemetry`: `hello` → `catalog` → `snapshot`, буфер одного снимка, отзыв доступа | готово | интеграционные тесты с реальным TLS и отпечатком |
| Окно WPF: QR, адрес, отпечаток, приглашение, датчики, сопряжённые телефоны | готово | снимок окна и живые значения |
| GPU, PDH-диски, LHM, история, пресеты, Android-клиент | не начато | — |

Известные ограничения проверки: поток на живом приложении проверен тестами того же кода, но не отдельным клиентом на телефоне; Android-устройство к машине не подключено.

### Отступления от проектных документов

- одно приглашение с TTL 300 с обслуживает и QR, и ручной ввод; отдельного 120-секундного QR-режима пока нет;
- порт по умолчанию 18443, при занятости хост пробует 18444 и 18445 и сообщает занятый порт в окне;
- `samplePeriodMs` равен периоду тика сборщика (1000 мс) и пока не зависит от группы датчика;
- медленный сокет закрывается кодом `1008` с причиной `slow_client`, отзыв доступа — `1008` `revoked`; коды `1002`, `1009` и `1011` зарезервированы за ошибками протокола, размера и сервера;
- зависший провайдер помечает свои датчики как `stale` с причиной `timed_out`, повторный опрос не запускается поверх незавершённого.

## Сборка и запуск

```powershell
. .\scripts\dev-env.ps1                                   # окружение сборки
dotnet build HardwareDisplay.slnx
dotnet test windows\tests\HardwareDisplay.Tests
windows\HardwareDisplay.Host\bin\Debug\net10.0-windows\HardwareDisplay.Host.exe
```

`scripts\dev-env.ps1` заполняет переменные `ProgramFiles`, `ProgramW6432` и `CommonProgramFiles`, если они пустые, и отключает переиспользование узлов MSBuild. Без этого NuGet на этой машине падает с `Value cannot be null. (Parameter 'path1')` при загрузке machine-wide конфигурации.

Проверка живого сервера сторонним клиентом (Python, без .NET):

```powershell
python tools\protocol-smoke.py --ip 192.168.0.203 --port 18443 `
    --host pc-<hostId>.hardwaredisplay.test --invite <32 hex> --fingerprint <64 hex>
```

Адрес, имя ПК, отпечаток и код приглашения показывает окно хоста. Клиент сверяет SHA-256 листа, проверяет `401` без токена, сопрягается и читает первые кадры потока.

## Структура репозитория

```text
hardwareDisplay/
  MAIN_PROMPT.md
  docs/                         Технический проект
  reports/                      Сводное исследование
  research_notes/               Доказательства и ограничения источников
  scripts/
    dev-env.ps1                 Окружение сборки для этой машины
    capture-window.ps1          Снимок окна хоста для проверки интерфейса
    ui-smoke.ps1                Проверка окна через UI Automation: запуск, стоп, повторный запуск
  tools/
    protocol-smoke.py           Сторонний клиент протокола для проверки живого сервера
  windows/
    HardwareDisplay.Core/       Каталог, расписание опроса, состояния, latest snapshot
    HardwareDisplay.Windows/    Win32-провайдеры и их арифметика
    HardwareDisplay.Host/       WPF, жизненный цикл, идентичность, Kestrel, сопряжение
    tests/HardwareDisplay.Tests/ Тесты сбора, идентичности, TLS и рассылки
  android/                      Compose-клиент: следующий этап
  protocol/v1/                  Фикстуры общих сообщений: следующий этап
  packaging/windows/            Установщик и правило firewall: этап 5
```

`Host` вызывает `Core` и `Windows`. `Core` знает только контракт провайдера. `Host` держит сеть, идентичность и окно; Android будет зависеть от контракта, зафиксированного в `PROTOCOL.md`.
