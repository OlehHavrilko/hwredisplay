# Аналоги Windows → мобильная панель

Проверка 12.11.2026 по исходному коду и документации разработчиков. Установки и сравнительные прогоны продуктов не проводились. Сведения о функциях из описаний продукта — заявления разработчиков. Отдельно помечены выводы статического чтения кода.

## Как устроен продукт со скриншотов

### Takeaway

С высокой уверенностью референс — [Xeakaes/PcHWmonitor](https://github.com/Xeakaes/PcHWmonitor). Совпали точное имя Windows-окна, формат `pchw://connect`, QR-подсказка, порт `8765` и шесть категорий истории. Точный установленный релиз по скриншотам не определяется. Исходный код проверен на `764c5e33b8c79e333b00be8e444aa5a3e6872b31`.

### Cited Findings

- Windows tray строит QR из IP, порта и токена. Исходник содержит тот же заголовок и текст под QR, что и скриншот. Токен из изображения для анализа не использовался. [Tray QR, строки 26–86](https://github.com/Xeakaes/PcHWmonitor/blob/764c5e33b8c79e333b00be8e444aa5a3e6872b31/server/tray.py#L26-L86), [CLI, строки 48–68](https://github.com/Xeakaes/PcHWmonitor/blob/764c5e33b8c79e333b00be8e444aa5a3e6872b31/server/cli.py#L48-L68).
- Windows-стек проекта — Python, FastAPI/Uvicorn, LibreHardwareMonitorLib через DLL или внешний LibreHardwareMonitor HTTP `/data.json`, `psutil` для дисков/сети, PresentMon как опция для FPS. В поставке один `.exe` из PyInstaller и UAC manifest. Есть режим симуляции. Android — Kotlin, Jetpack Compose, Material 3, Room. [README, архитектура и сборка](https://github.com/Xeakaes/PcHWmonitor/blob/764c5e33b8c79e333b00be8e444aa5a3e6872b31/README.md#4-architecture).
- `/ws` принимает первым сообщением `auth` с общим токеном при включённой проверке, использует тайм-аут и `compare_digest`, затем отправляет `welcome` и регистрирует клиента. CLI выдаёт случайный токен при отсутствии `--token`, WSS опционален. Клиент имеет backoff, ping 15 с и путь с SPKI pin для доверенного ключа. QR сам по себе не передаёт pin в показанном формате. [Server auth](https://github.com/Xeakaes/PcHWmonitor/blob/764c5e33b8c79e333b00be8e444aa5a3e6872b31/server/app.py#L118-L178), [CLI TLS](https://github.com/Xeakaes/PcHWmonitor/blob/764c5e33b8c79e333b00be8e444aa5a3e6872b31/server/cli.py#L48-L125), [WebSocketClient](https://github.com/Xeakaes/PcHWmonitor/blob/764c5e33b8c79e333b00be8e444aa5a3e6872b31/app/src/main/java/com/Obscrum/pchwmonitor/data/network/WebSocketClient.kt#L55-L205).
- Hub читает источник один раз в тике (по умолчанию 1 с) через `asyncio.to_thread`, сериализует снимок и рассылает его параллельно. Цикл ожидает общий `gather` отправок. Для отдельной отправки есть 2 с тайм-аут с последующим отключением. Это позволяет обосновать эксперимент с медленным клиентом при сравнении. [Hub, строки 10–77](https://github.com/Xeakaes/PcHWmonitor/blob/764c5e33b8c79e333b00be8e444aa5a3e6872b31/server/hub.py#L10-L77).
- `StatusMessage` — фиксированные nullable-поля `cpu`, `gpu`, `igpu`, `ram`, `disk`, `net`, `fans`, `fps` и общий `available`; отдельные `usagePct`, `tempC`, `hotspotC`, `vramUsedMb` и `vramTotalMb`. Нет общего каталога со стабильными ID датчиков в этой схеме. История хранит фиксированный набор из температуры/загрузки CPU, температуры/загрузки/Hotspot GPU и загрузки RAM, фильтрует по `pcId` и чистит данные старше часа. Это соответствует шести метрикам в референсах. [Schema, строки 10–82](https://github.com/Xeakaes/PcHWmonitor/blob/764c5e33b8c79e333b00be8e444aa5a3e6872b31/server/schema.py#L10-L82), [HistoryRepository, строки 5–27](https://github.com/Xeakaes/PcHWmonitor/blob/764c5e33b8c79e333b00be8e444aa5a3e6872b31/app/src/main/java/com/Obscrum/pchwmonitor/data/local/HistoryRepository.kt#L5-L27).
- README описывает перестановку, скрытие, закрепление и изменение ширины карточек, альбомную сетку, палитры, несколько одновременных ПК, историю и опциональный Cloudflare Tunnel. По скриншотам эти функции не следует считать отсутствующими или сломанными. Android и сервер самого PcHWmonitor опубликованы под AGPL-3.0. Для компонентов поставки использовать лицензии каждого фактически выбранного upstream-артефакта. [Функции и лицензия](https://github.com/Xeakaes/PcHWmonitor/blob/764c5e33b8c79e333b00be8e444aa5a3e6872b31/README.md#1-features), [Лицензия PcHWmonitor](https://github.com/Xeakaes/PcHWmonitor/blob/764c5e33b8c79e333b00be8e444aa5a3e6872b31/LICENSE).

### Inferences

- Использовать референс как доказательство реализуемости сценария, а не как основание копировать код или UX. Существенные точки отличия HardwareDisplay — произвольные датчики и диски через каталог, управляемые пресеты, понятные причины отсутствия данных, отдельные учётные данные телефона с отзывом, WSS с верифицированной идентичностью ПК.
- При `ws://` общий токен передаётся внутри нешифрованного сообщения. Переиспользовать этот сценарий для релиза не требуется. В QR-обработчике прототипа исключить вывод payload в логи, поскольку референс включает его в исключительный путь логирования. Установить независимый тайм-аут отправки клиенту и ограниченную очередь снимков, а не ждать сетевых отправок перед следующим замером. Это выводы статического чтения, не результаты тестов. [CLI](https://github.com/Xeakaes/PcHWmonitor/blob/764c5e33b8c79e333b00be8e444aa5a3e6872b31/server/cli.py#L125-L164), [QR error handling](https://github.com/Xeakaes/PcHWmonitor/blob/764c5e33b8c79e333b00be8e444aa5a3e6872b31/server/tray.py#L63-L86), [Hub](https://github.com/Xeakaes/PcHWmonitor/blob/764c5e33b8c79e333b00be8e444aa5a3e6872b31/server/hub.py#L30-L77).

### Gaps

- Не проверены точный релиз пользователя, конкретные отказы на его ПК, температура CPU и поведение под нагрузкой. Сообщение «нет данных» на скриншоте не устанавливает причину.

## Что реализовано у других производителей

### Takeaway

Есть три проверяемых семейства решений: нативный Android-клиент с Windows-сервером, браузерный экран с редактором на ПК и независимые провайдеры датчиков с общей системой панелей. Пресеты и редакторы уже встречаются. Смысл сравнения для HardwareDisplay — глубина настройки с телефона, поведение при смене железа и сети и стоимость сопровождения.

### Inferences

- Из MoBro и Pitikapp следует проектное решение разделить переносимый смысл метрики (`gpu.temperature.core`, `gpu.temperature.hotspot`) и конкретную привязку к датчику ПК. При смене сервера подсказывать доступные кандидаты, требовать выбора при неоднозначности и визуально сохранять место неподключённой карточки.
- Из Trigone и Pitikapp следует испытать автообнаружение отдельно от базового QR, ручного адреса и локальной авторизации. Ручной сценарий остаётся рабочим при отсутствии multicast/broadcast. Ошибки TCP и TLS лучше показывать раздельно, а сеть гостевого Wi‑Fi с изоляцией клиентов включить в матрицу.
- Для v1 собственный нативный редактор Android покрывает сценарий пользователя. Браузерный thin client хорош как диагностический инструмент и самостоятельное будущее решение с другой моделью доверия и UX. AIDA64 показывает достаточность одностороннего SSE для пассивной панели, однако требуемый WebSocket удобен для двустороннего состояния, подписок и версионирования сообщений.
- Для воспроизводимого сравнения брать один и тот же ПК и один телефон, отмечать конкретные версии, измерять время до первого замера, ошибки после сна и перезапуска, корректность перестройки графиков, ручное переподключение при смене IP, FPS игры и загрузку CPU сборщиком. Покрытие продвинутых метрик сравнивать по названию источника и смыслу. Метрики на странице магазина не подменяют испытания.

### Gaps

- Объём рынка, доля неработающих функций, доступность конкретных датчиков у разных плат и реальный overhead конкурентов не установлены. Матрица использует заявленные возможности и код, где он открыт.
