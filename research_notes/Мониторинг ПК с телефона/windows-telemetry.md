# Источники телеметрии Windows

Проверка документации и исходников на 12 ноября 2026 года. Матрица ниже описывает способы получения данных и условия, которые предстоит проверить. Замеры на физическом ПК в рамках исследования не проводились.

## Как использовать HWiNFO

### Takeaway

HWiNFO подходит для сверки и как дополнительный источник для пользователей, которые уже его установили. Для автономной работы HardwareDisplay лучше спроектировать собственный сборщик с заменяемыми провайдерами. Встраиваемый SDK HWiNFO остаётся отдельным вариантом поставки.

### Cited Findings

- В обычном HWiNFO64/ARM64 Shared Memory Support ограничен 12 часами работы. На странице лицензий эти же 12 часов относятся к Remote Sensor Monitoring, который использует Shared Memory. Personal не даёт права коммерческого использования. [Таблица лицензий HWiNFO](https://www.hwinfo.com/licenses/)
- EULA требует явного одобрения правообладателя для встраивания и включения HWiNFO в комплект стороннего ПО. Обход лимита SHM запрещён, включая автоматизацию действий для его обхода. [Лицензия HWiNFO](https://www.hwinfo.com/files/license.pdf)
- SDK предлагается как интегрируемая DLL с прямым API инвентаризации и мониторинга датчиков. Автор прямо пишет, что SDK приобретается отдельно от HWiNFO Pro. [HWiNFO SDK](https://www.hwinfo.com/sdk/), [разъяснение автора](https://www.hwinfo.com/forum/threads/sdk.10694/)
- Есть опубликованный интерфейс SHM и отдельный пример Remote Sensor Monitor, который отдаёт показания из HWiNFO и других программ как JSON через HTTP. Это пример архитектуры внешнего источника плюс локальный сетевой сервер. [Раздел Shared Memory Interface](https://www.hwinfo.com/forum/forums/shared-memory-interface.13/), [официальный каталог дополнений](https://www.hwinfo.com/add-ons/), [тема автора Remote Sensor Monitor](https://www.hwinfo.com/forum/threads/introducing-remote-sensor-monitor-a-restful-web-server.1025/)

### Inferences

- Использовать HWiNFO Sensors как сравнительный эталон только на правильно лицензированной конфигурации. Для опционального SHM-адаптера различать выключенный SHM, остановку внешнего процесса, несовместимость формата и зависший поток замеров. Подключаться к уже запущенному пользователем HWiNFO в режиме чтения и сверить условия выбранного сценария использования до поставки интеграции.
- Если нужен SDK, запросить у правообладателя условия по распространению, поддерживаемой архитектуре, частоте обновлений и поставке драйверных компонентов. Данные о цене и покрытии конкретной модели в публичных источниках не зафиксированы.

### Gaps

- Не подтверждены коммерческие условия для конкретного продукта и цена SDK. Формат SHM, доступ из разных контекстов Windows и точное поведение на границе 12 часов ещё не проверены прототипом.

## Что покрывает LibreHardwareMonitor и где нужны права

### Takeaway

LibreHardwareMonitorLib — кандидат для расширенных датчиков, особенно температур CPU и платы. Ключевые риски зависят от версии библиотеки, драйвера, конкретного датчика и режима Windows. Сетевой процесс можно оставить с обычными правами и получать измерения от отдельного локального процесса, когда датчикам нужны повышенные права.

### Cited Findings

- Стабильный релиз, проверенный в upstream — `v0.9.6`, 14 февраля 2026, `3d331e3`. NuGet публикует `LibreHardwareMonitorLib 0.9.6`. Тег содержит цели .NET Framework 4.7.2, .NET Standard 2.0, .NET 8/9/10 и Windows RID x64/x86/arm64. Список платформ в проекте не подтверждает одинаковое покрытие датчиков на всех этих платформах. [Релиз v0.9.6](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor/releases/tag/v0.9.6), [NuGet](https://www.nuget.org/packages/LibreHardwareMonitorLib/0.9.6), [файл проекта](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor/blob/v0.9.6/LibreHardwareMonitorLib/LibreHardwareMonitorLib.csproj)
- API библиотеки группирует оборудование и подустройства. `Computer.Open()` активирует выбранные категории, сборщик обновляет оборудование и читает сенсоры. README указывает, что некоторым датчикам нужны права администратора. [README v0.9.6](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor/blob/v0.9.6/README.md), [Computer.cs v0.9.6](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor/blob/v0.9.6/LibreHardwareMonitorLib/Hardware/Computer.cs)
- В `v0.9.5` upstream заменил WinRing0 на PawnIO. `v0.9.6` обращается к устройству PawnIO и загружает подписанные модули из ресурсов. README этих ресурсов указывает версию модулей `0.1.6`, а релиз упоминает совместимость с PawnIO 2.2. Для теста фиксировать отдельно версию драйвера и версию модулей. В выпуске PawnIO Setup `2.2.0` появилась возможность открыть устройство непривилегированным пользователям, которую автор считает нежелательной. Автор рекомендует высокоуровневый сервис вместо выдачи пользователям прямого доступа. [Переход на PawnIO](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor/releases/tag/v0.9.5), [ресурсы v0.9.6](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor/tree/v0.9.6/LibreHardwareMonitorLib/Resources/PawnIo), [код PawnIo](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor/blob/v0.9.6/LibreHardwareMonitorLib/PawnIo/PawnIo.cs), [PawnIO Setup 2.2.0](https://github.com/namazso/PawnIO.Setup/releases/tag/2.2.0), [комментарии автора об ACL](https://github.com/namazso/PawnIO.Setup/issues/12)
- Microsoft классифицирует WinRing0 как уязвимый драйвер, CVE-2020-14979. Microsoft указывает, что Windows 11 2022 Update включил список блокируемых драйверов по умолчанию. Он также применяется при активной целостности памяти, Smart App Control или S mode с документированными исключениями. [WinRing0 и Defender](https://support.microsoft.com/en-us/windows/security/threat-malware-protection/microsoft-defender-antivirus-alert-vulnerabledriver-winnt-winring0), [политика блокировки](https://learn.microsoft.com/en-us/windows/security/application-security/application-control/app-control-for-business/design/microsoft-recommended-driver-block-rules)
- В теге AMD GPU использует ADL/PMLog и D3D, NVIDIA — NVAPI, NVML и D3D, в релиз добавлены показания IGCL для поддерживаемых Intel iGPU. Для накопителей код использует DiskInfoToolkit и `IOCTL_DISK_PERFORMANCE`. AMD CPU код различает `Tctl`, `Tdie`, `Tctl/Tdie`. Это подтверждает, что единый API LHM объединяет разнородные низкоуровневые источники. [AmdGpu.cs](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor/blob/v0.9.6/LibreHardwareMonitorLib/Hardware/Gpu/AmdGpu.cs), [NvidiaGpu.cs](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor/blob/v0.9.6/LibreHardwareMonitorLib/Hardware/Gpu/NvidiaGpu.cs), [релиз и IGCL](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor/releases/tag/v0.9.6), [StorageDevice.cs](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor/blob/v0.9.6/LibreHardwareMonitorLib/Hardware/Storage/StorageDevice.cs), [Amd17Cpu.cs](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor/blob/v0.9.6/LibreHardwareMonitorLib/Hardware/Cpu/Amd17Cpu.cs)
- Библиотека — MPL-2.0 с отдельными уведомлениями о компонентах. MPL требует предоставить получателю доступ к исходной форме MPL-кода и сохранять уведомления при распространении исполняемой формы. Новые файлы larger work могут иметь отдельную лицензию. В `THIRD-PARTY-NOTICES` указаны BSD для Aga.Controls и LGPL для PawnIO.Modules, в конкретном модуле `AMDFamily17` указан `LGPL-2.1-or-later`. Исходники драйвера PawnIO 2.2.0 опубликованы под GPL v2 или новее с описанным специальным исключением. Текст для драйвера, его установщик и встраиваемые модули следует проверять отдельно. [MPL §3](https://www.mozilla.org/en-US/MPL/2.0/), [Mozilla FAQ](https://www.mozilla.org/en-US/MPL/2.0/FAQ/), [уведомления LHM](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor/blob/v0.9.6/THIRD-PARTY-NOTICES.txt), [PawnIO 2.2.0](https://github.com/namazso/PawnIO/blob/2.2.0/README.md), [модуль AMDFamily17](https://github.com/namazso/PawnIO.Modules/blob/0.1.6/AMDFamily17.p)
- Прямые пакеты тега включают `DiskInfoToolkit 1.1.2`, `HidSharp 2.6.4`, `RAMSPDToolkit-NDD 1.4.2`, `System.Management 10.0.2`, `System.Threading.AccessControl 10.0.3`, другие условные зависимости и `Microsoft.Windows.CsWin32` с `PrivateAssets=all`. Реальный набор runtime-зависимостей нужно получить для выбранного RID и режима публикации. [Файл проекта](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor/blob/v0.9.6/LibreHardwareMonitorLib/LibreHardwareMonitorLib.csproj), [DiskInfoToolkit](https://www.nuget.org/packages/DiskInfoToolkit/1.1.2), [HidSharp](https://www.nuget.org/packages/HidSharp/2.6.4), [RAMSPDToolkit-NDD](https://www.nuget.org/packages/RAMSPDToolkit-NDD/1.4.2)
- LHM содержит также код управления вентиляторами. В AMD GPU путь `ControlMode.Undefined` возвращает управление без установки скорости, другие режимы могут вызвать запись. Начальный режим по умолчанию определяется через `ISettings` как `Undefined`. [Control.cs](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor/blob/v0.9.6/LibreHardwareMonitorLib/Hardware/Control.cs), [AmdGpu.cs](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor/blob/v0.9.6/LibreHardwareMonitorLib/Hardware/Gpu/AmdGpu.cs)

### Inferences

- `WindowsCountersProvider` — базовый процесс с обычными правами. `LibreHardwareMonitorProvider` — подключаемый источник для конкретных групп и версий. Если нужны права, `SensorHelper` работает отдельно и отдаёт узкий контракт замеров по локальному IPC с ACL для ожидаемого пользователя. Держать WebSocket, токены сопряжения и разбор клиентских сообщений вне привилегированного процесса. Опрашивать каждую группу только один раз за цикл и изолировать зависание медленного источника.
- Зафиксировать режим чтения на уровне приложения и настроек провайдера. Использовать собственные чистые `ISettings`, отбрасывать сохранённые настройки управления из внешних приложений, не вызывать `IControl`, не открывать наружу запись или сырые команды PawnIO. Оставить опциональные группы контроллеров и EC вне начального эксперимента и проверять их отдельно.
- Для прототипа начать с локальной установки официальной версии PawnIO пользователем там, где понадобится. Для публичной сборки отдельно подтвердить точные условия перепоставки скачиваемого установщика и всех бинарных компонентов, составить SBOM по фактическому publish и комплект уведомлений плюс указатели на точные исходники. WinRing0, ослабление ACL PawnIO и изменение настроек защиты не входят в предлагаемый путь.

### Gaps

- Не проверено поведение PawnIO с конкретными BIOS, Secure Boot, HVCI, Defender и античитами. Нужны тесты под обычным пользователем с PawnIO и без него, после установки/перезагрузки и при отказе источника. Не подтверждены право на включение выбранного EXE установщика PawnIO в дистрибутив HardwareDisplay и полная цепочка транзитивных лицензий будущей сборки.

## Что доступно штатно и как проверить совместимость

### Takeaway

Первый сквозной прототип может начать с реальной загрузки CPU и RAM через Windows. Дальше WDDM и API вендоров добавят GPU и VRAM. Температуры, мощность, напряжения и SMART нужно обещать по результатам на конкретных конфигурациях и с указанием источника каждой метрики.

### Cited Findings

| Метрика | Кандидат для реализации | Условия и смысл |
| --- | --- | --- |
| CPU, время занятости | `GetSystemTimes` или PDH `Processor Information` | Для `GetSystemTimes` процент из двух замеров `100 × (Δkernel + Δuser − Δidle)/(Δkernel + Δuser)`. Время kernel включает idle, на системах с более чем 64 логическими CPU вызов ограничен группой вызывающего потока. Определить отдельную семантику для Task Manager-style utility. [GetSystemTimes](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getsystemtimes), [сбор PDH](https://learn.microsoft.com/en-us/windows/win32/perfctrs/collecting-performance-data) |
| RAM занято/всего | `GlobalMemoryStatusEx` | `ullTotalPhys − ullAvailPhys`. Available включает standby, free и zero. Общая физическая RAM, commit и объём установленных модулей — отдельные показатели. [MEMORYSTATUSEX](https://learn.microsoft.com/en-us/windows/win32/api/sysinfoapi/ns-sysinfoapi-memorystatusex), [память в Win32](https://learn.microsoft.com/en-us/windows/win32/memory/memory-performance-information) |
| CPU температура и электрические значения | LHM/PawnIO, HWiNFO SDK/SHM | Температура CPU package, `Tctl` и `Tdie` должны сохранять свои семантики. Microsoft отмечает, что `Win32_TemperatureProbe.CurrentReading` не заполняется в текущих реализациях WMI. [WMI](https://learn.microsoft.com/en-us/windows/win32/cimwin32prov/win32-temperatureprobe), [AMD CPU в LHM](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor/blob/v0.9.6/LibreHardwareMonitorLib/Hardware/Cpu/Amd17Cpu.cs) |
| GPU, активность движков | Кандидат `GPU Engine(*)\Utilization Percentage` через PDH/WDDM | Task Manager берёт показатель самого загруженного движка. Для прототипа на PDH разобрать реальные имена экземпляров, сопоставить LUID и физический GPU, группировать по движку внутри адаптера. Сумма вкладов PID в одном движке, затем максимум по движкам — гипотеза для сверки. Несколько параллельных движков нельзя просто складывать в общий процент. WDDM показатель GPU Busy может отличаться от vendor GPU Core Load. [Microsoft DirectX о Task Manager](https://devblogs.microsoft.com/directx/gpus-in-the-task-manager/), [SysMon/PIX](https://learn.microsoft.com/en-us/windows/win32/direct3dtools/pix/articles/timing-captures/pix-timing-captures) |
| GPU, dedicated/shared memory | Кандидат `GPU Adapter Memory(*)\Dedicated Usage` и `Shared Usage`, ёмкость из `DXGI_ADAPTER_DESC1.DedicatedVideoMemory` | Проверить наличие и значения adapter-level счётчика на тестовых версиях WDDM. `IDXGIAdapter3::QueryVideoMemoryInfo` возвращает текущие usage/budget приложения для узла и segment group. Это годится для бюджета процесса. Microsoft фиксирует неверные `GPU Process Memory` счётчики при некоторых сценариях и двойной учёт shared allocations по процессам. На UMA не вычислять заполнение VRAM при нулевой/неприменимой dedicated ёмкости. [DXGI описание адаптера](https://learn.microsoft.com/en-us/windows/win32/api/dxgi/ns-dxgi-dxgi_adapter_desc1), [семантика DXGI](https://learn.microsoft.com/en-us/windows/win32/api/dxgi1_4/ns-dxgi1_4-dxgi_query_video_memory_info), [ошибка счётчиков](https://learn.microsoft.com/en-us/troubleshoot/windows-client/performance/gpu-process-memory-counters-report-wrong-value), [агрегация Task Manager](https://devblogs.microsoft.com/directx/gpus-in-the-task-manager/) |
| GPU AMD | ADLX `IADLXGPUMetrics`, `IADLXGPUMetricsSupport`, `IADLXGPUMetrics1` | Доступность проверяется по карте. Есть GPU usage, GPU VRAM в MB, GPU temperature, hotspot, clocks, power и fan speed. Расширенный интерфейс даёт температуру памяти, если она поддерживается. ADLX runtime поставляется с AMD display driver. Документация отдельно описывает повторную инициализацию Windows service после нового логина. LHM в данном теге использует ADL, поэтому ADLX — самостоятельный провайдер либо диагностический инструмент. [Метрики AMD](https://gpuopen.com/manuals/adlx/adlx-sdk-references/adlx-interfaces/performance-monitoring/iadlxgpumetrics/), [поддержка метрик](https://gpuopen.com/manuals/adlx/adlx-sdk-references/adlx-interfaces/performance-monitoring/iadlxgpumetricssupport/), [расширенные метрики](https://gpuopen.com/manuals/adlx/adlx-sdk-references/adlx-interfaces/performance-monitoring/iadlxgpumetrics1/), [Quick Start](https://gpuopen.com/manuals/adlx/programming-with-adlx/adlx-programming-guide/quick-start/), [ADLX в сервисе](https://gpuopen.com/manuals/adlx/programming-with-adlx/adlx-programming-guide/advanced-configurations/using-adlx-in-a-windows-system-service-application/) |
| GPU NVIDIA | NVML и NVAPI из установленного драйвера | NVML поддерживает запросы температуры, памяти, загрузки, частот и питания с ограничениями устройства. `nvmlUtilization_t.memory` — доля времени, когда память читалась или записывалась, а `memoryInfo.used` — байты по определению API, с оговоркой об управлении памятью Windows при WDDM. `memory busy`, `VRAM bytes`, `VRAM fill %` хранить раздельно. Отдельный hotspot или температура памяти проверяются по поддержке конкретного API/модели. [NVML](https://docs.nvidia.com/deploy/nvml-api/nvml-api-reference.html), [Device Queries](https://docs.nvidia.com/deploy/nvml-api/latest/api/group__nvmlDeviceQueries.html), [nvmlUtilization_t](https://docs.nvidia.com/deploy/nvml-api/latest/api/structnvmlUtilization__t.html), [NVAPI](https://docs.nvidia.com/nvapi/concepts.html) |
| GPU Intel | IGCL, у Intel включает 64-bit телеметрию; WDDM для общего пути | Устанавливается с Intel graphics driver. Поддержка телеметрии зависит от устройства, драйвера и вызова. Проверить Arc dGPU и iGPU отдельно. [Intel IGCL](https://github.com/intel/drivers.gpu.control-library), [спецификация Intel](https://intel.github.io/drivers.gpu.control-library/) |
| Накопители, активность и пропускная способность | PDH `PhysicalDisk`, отдельно байты/с чтение/запись; `IOCTL_DISK_PERFORMANCE` в LHM | Microsoft описывает per-drive `Physical Disk` counters. Для метрики активности выбрать и подписать точную семантику, например долю времени активности `100 − % Idle Time` при валидном счётчике. Не выдавать сетевой, логический или агрегированный диск за отдельное физическое устройство. [Physical Disk counters](https://learn.microsoft.com/en-us/windows-server/storage/storage-spaces/performance-history-for-drives), [LHM StorageDevice](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor/blob/v0.9.6/LibreHardwareMonitorLib/Hardware/Storage/StorageDevice.cs) |
| Накопители, температура и здоровье | `MSFT_StorageReliabilityCounter`, IOCTL NVMe SMART/Health, LHM/DiskInfoToolkit | Windows умеет запрашивать NVMe log pages через `IOCTL_STORAGE_QUERY_PROPERTY`; доступ и наличие значений зависят от устройства, контроллера и драйвера. Не смешивать Composite Temperature и датчики накопителя. USB-мост, RAID и SATA проверить отдельными строками матрицы. [Microsoft NVMe](https://learn.microsoft.com/en-us/windows/win32/fileio/working-with-nvme-devices), [StorageReliabilityCounter](https://learn.microsoft.com/en-us/windows-hardware/drivers/storage/msft-storagereliabilitycounter) |
| Плата, вентиляторы, VRM, RAM SPD | LHM/PawnIO или HWiNFO | Показания зависят от чипа Super I/O, встроенного контроллера и профиля платы. Даже в одном релизе есть отдельные исправления для разных моделей. [История изменений LHM v0.9.6](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor/releases/tag/v0.9.6) |

- Для локализованных Windows есть `PdhAddEnglishCounterW`; для шаблонов учитывай описанную Microsoft обработку wildcard и статус каждой строки при `PdhGetFormattedCounterArrayW`. Часть счётчиков требует двух замеров. [PdhAddEnglishCounterW](https://learn.microsoft.com/en-us/windows/win32/api/pdh/nf-pdh-pdhaddenglishcounterw), [PdhGetFormattedCounterArrayW](https://learn.microsoft.com/en-us/windows/win32/api/pdh/nf-pdh-pdhgetformattedcounterarrayw)
- Microsoft документирует `D3DKMTQueryStatistics` как зарезервированный для системы API. DXCore отдельно перечисляет adapter-level memory usage, engine running time и temperature в документе с оговоркой о prerelease. Его можно исследовать через `IsQueryStateSupported` для конкретного Windows build и GPU, не делать единственным основанием обещаний совместимости. [D3DKMTQueryStatistics](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/d3dkmthk/nf-d3dkmthk-d3dkmtquerystatistics), [DXCoreAdapterState](https://learn.microsoft.com/en-us/windows/win32/api/dxcore_interface/ne-dxcore_interface-dxcoreadapterstate), [перечисление DXCore адаптеров](https://learn.microsoft.com/en-us/windows/win32/dxcore/dxcore-enum-adapters)
- LUID связывает WDDM/DXGI данные в рамках текущей сессии Windows. Уникальность гарантирована до перезапуска системы. Идентификатор присоединения показаний в одном сеансе и постоянный ID карточки должны жить отдельно. [Microsoft ID3D12Device::GetAdapterLuid](https://learn.microsoft.com/en-us/windows/win32/api/d3d12/nf-d3d12-id3d12device-getadapterluid)

### Inferences

- Источник и определение — часть контракта метрики. Например, `gpu.engine_busiest.percent` и `gpu.vendor_core_busy.percent`, `gpu.memory.dedicated.used.bytes` и `gpu.memory.activity.percent` должны иметь отдельные семантические ключи. Не объединять в одну линию показания с разной семантикой или разной точкой измерения. Соотношение `used/total` вычислять только для совместимого источника, того же устройства и применимой положительной ёмкости.
- Постоянный `deviceId` хранить на ПК и восстанавливать по доступным стабильным PnP/vendor идентификаторам, а при неоднозначности (две одинаковые карты, смена устройства) фиксировать потерю привязки. Имя и индекс не подходят для уникальности. В Android отдавать непрозрачный `deviceId`, без необходимости передавать сырые серийные номера или PID.
- Контракт замера хранит значение, единицу, фактическое время, окно усреднения при наличии, источник, статус и причину. Различать валидный 0, нет первого дифференциального замера, счётчик отсутствует, доступ закрыт, ошибка чтения и устаревание. При сбросе накопительных счётчиков и перезапуске устройства начать новое окно. Если у провайдера свежесть недоступна, фиксировать время опроса как таковое, не выдавая его за аппаратную метку времени.
- Стартовые частоты как гипотезы: Windows CPU/RAM/активность GPU/диска и отправка на телефон 1 с; тяжёлые опросы SMART/EC отдельно и реже, начальный кандидат 5–10 с. Измерить длительность каждого прохода, частоту фактического обновления, долю невалидных точек, задержку до Android, CPU и память. Одновременный запуск HWiNFO и другого EC/SMBus-опроса требует отдельной проверки, поэтому начать со сравнения повторяемых прогонов, затем проверить безопасный совместный запуск выбранных групп.
- Матрица стендов: AMD Ryzen с Radeon, Intel с iGPU, гибридный ноутбук Intel/NVIDIA, отдельная NVIDIA, Intel Arc по доступности, два GPU одного производителя по доступности. Накопители: NVMe, SATA, USB-мост, RAID по доступности. Windows 11 x64 с обычной учётной записью и включёнными стандартными средствами защиты; конкретный Windows 10 билд, ARM64 и серверную версию тестировать только при решении поддерживать. Версию ОС, драйвера GPU, провайдера, PawnIO/модулей и BIOS записывать в журнал стенда.
- Тестовые нагрузки: CPU-only, 3D, compute и video decode/encode раздельно; отдельная проверка выделения VRAM и работы GPU при постоянном объёме выделенной VRAM; RAM allocation/release; чтение/запись на выбранном диске; idle, sleep/resume, отключение/подключение GPU или смена драйвера. Сверять эквивалентные счётчики с PerfMon/Task Manager и датчики с HWiNFO или вендорным инструментом при одинаковых нагрузке, единицах и окне. Пропуски, дрейф и неподдерживаемые поля записывать явно, пороги расхождения утверждать после пилотного прогона.

### Gaps

- Не проверены наличие, локализация, формат экземпляров и агрегация `GPU Engine`/`GPU Adapter Memory` на целевых билдах и драйверах. Не проверены ADLX/NVML/IGCL на фактическом ПК пользователя и точное соответствие метрик HWiNFO. Совместимость одной конфигурации не переносится автоматически на соседнее поколение CPU/GPU, другой BIOS или Windows build.
